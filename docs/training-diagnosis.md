# 可读性问题诊断与续训

本实验继续维护自己的 PyTorch 实现，以控制变量定位原因，不引入其他训练项目或预训练权重。之前的 500 万字符、726 万参数模型只训练 6,000 步，尚未达到可读性门槛。

## 已完成的诊断

- 标签窗口为 `x=t[0:T]`、`y=t[1:T+1]`，不跨文章或数据划分；测试覆盖最后窗口及短文本忽略标签。
- 修改未来 token 不改变此前 logits；手写注意力的前向和输入/QKV/输出投影梯度与 PyTorch 因果注意力参考算子吻合。参考算子只用于测试，模型仍保留显式实现。
- 第 6,000 步模型在固定诊断抽样上，末位置正常前文 loss 4.1114，打乱前文 4.9881，只保留当前 token 5.2217。模型使用了上下文；打乱同时改变位置、单 token 同时重置位置，因此不能把差值解释为纯粹的语义能力。
- 各层均有非零、有限梯度。CPU/MPS 最大 logits 差约 9.54e-6，第一层 QKV 梯度差约 1.08e-7，未发现设备导致的明显数值异常。
- 旧训练固定验证 loss 从 5,000 步的 4.3407 降到 6,000 步的 4.2755；当时停止的依据是预算，而非已经收敛。

上述检查未发现目标错位、未来信息泄漏或梯度断路，不能据此保证所有实现与超参数都最优。优先检验训练不足，比同时改数据和模型更容易解释结果。

诊断记录：`runs/diagnosis/baseline.json`；最早探索脚本结果为 `runs/diagnosis/audit.txt`，抽样过程不同，数值不应直接混用。可复现入口：

```sh
uv run python -m micro_rsi.evaluation.diagnostics \
  --checkpoint artifacts/checkpoints/wiki-zh-medium/last.pt \
  --output runs/diagnosis/my-baseline.json
```

## 数据问题的证据

训练集 3,411 篇、5,000,883 字符；数字占 5.26%，ASCII 字母占 2.47%，出现 30,519 处三或四位数字年份，878 篇含空括号。空括号说明此前“字符量达标”不等于文本完整，外文名或模板信息可能在上游抽取时丢失。不能仅凭这些统计推断全部都是脏数据，也不能把自然年份直接删除。原始统计在 `runs/diagnosis/corpus-audit.json`。

百科中的日期、地名、译名和知识跨度对小字符模型有难度；目前把它列为后续语料质量实验的候选原因，本轮续训保持数据不变。

## 续训实验

使用 `configs/pretrain/wiki_zh_medium_continue.toml`，从旧 `last.pt` 的 6,000 步恢复至累计 14,000 步；模型、词表、数据、批大小保持不变。学习率从 3e-4 余弦降至 3e-5。本轮同时延长预算和改变后段学习率，因此只能评估此续训方案整体效果，不能单独归因于其中一项。新增 3,276.8 万 token 位置，累计 5,734.4 万；随机窗口会重叠，这不是独立语料量。

```sh
uv run micro-rsi train \
  --config configs/pretrain/wiki_zh_medium_continue.toml \
  --resume artifacts/checkpoints/wiki-zh-medium/last.pt
```

恢复会校验数据、模型、词表、设备等，拒绝覆盖输出；完整规则见 [工程约定](engineering.md)。CPU 分段恢复与连续训练逐位一致测试已通过；MPS 的 20 步短跑恢复起点验证 loss 与旧记录完全一致，为 4.2755418。正式模型根据验证集选择，旧测试集若再次使用须标记为复用基准。既有可读性前缀已被查看，属于开发评估，不能再声称为全新盲测。

## 实际结果与解释

本机 MPS 追加 8,000 步，训练更新约 1,560 秒，包含验证、保存和采样的总耗时约 1,610 秒。最佳验证点在累计 14,000 步。

| 指标 | 6,000 步 | 14,000 步 |
| --- | ---: | ---: |
| 固定训练窗口 loss | 3.8775 | 3.3875 |
| 固定验证窗口 loss | 4.2755 | 4.0358 |
| 完整验证 loss | 4.2218 | 3.9749 |
| 相同短续写量表局部通过数 | 3/24 | 7/24 |
| 句子平均分（0～2） | 0.125 | 0.292 |
| 模型可读性门槛 | 未通过 | 未通过 |

完整验证对 150,550 个目标计分；本轮未再次打开测试集。固定验证与完整验证的窗口方式不同，不能混用。短续写是既有开发集上的 Agent 主观复核；旧模型相同文本严格沿用历史评分，减少评分漂移，新增模型逐条复核。量表只要求局部句意可理解，不评事实正确；7 份通过不表示整段通顺，更不是可靠知识生成。量表阈值保持不变。所有样本和评分在 `runs/readability-continue/`，其中 `current` 指旧的 726 万参数模型，`medium` 指同一个模型续训后，不代表本轮改变尺寸。

相同前缀 `这座城市位于`、seed 42、temperature 0.7，新模型输出：

```text
这座城市位于市区。
法国国家统计与经济研究所（简称“”）在进行数据统计时，将布律埃及相邻的另外402个市镇设为（），并将包括核心区在内的周边共1,949个市镇划为。自202
```

可辨的句法比旧模型改善，但空引号、空括号、缺少分类名称仍严重损害可读性。模型学会复制不完整的百科格式，是数据问题会传递到生成中的具体证据；不是“只要训练久就自然消失”。仍有年份堆叠、名词重复、句子搭配错误和主题漂移。

这轮确认续训方案有效，旧预算过早停止；但没有解决稳定可读性。训练 loss 与验证 loss 差距扩大，不能无限重复同一份数据。下一轮优先用本地已有原件做文本完整性检查，识别模板句、缺失字段和异常段落，建立适合连续中文叙述的子集并进行等预算对照。不要机械删除所有数字或括号；保留合法日期、正常括注，记录每条清洗规则的误伤案例、保留量和文章划分。其中空白与空字段规则已按下节实施并完成短跑；其余质量筛选和正式对照尚未完成，不声称已找到全部根因。

最新生成命令：

```sh
uv run micro-rsi generate \
  --checkpoint artifacts/checkpoints/wiki-zh-medium-continue/best.pt \
  --prompt '这座城市位于' --max-new-tokens 80 --temperature 0.7 --seed 42
```

训练摘要在 `runs/wiki-zh-medium-continue/summary.json`，完整验证在 `runs/diagnosis/continued-evaluation.json`。恢复与注意力参考等检查共 21 项测试通过；这是工程正确性的证据，不是语言质量保证。

续训后在相同诊断抽样上，正常末位置 loss 从 4.1114 降至 3.9127，打乱前文为 5.0480，只保留当前 token 为 5.1122；记录在 `runs/diagnosis/continued.json`。进一步检查清洗实现发现 `re.sub(r"\s+", "", line)` 会连英文单词间空格一起删除，这是已按下节修复的具体预处理缺陷。旧实验数据保持冻结，尚未把更改后的语料用于正式训练，不能宣称该项修复带来生成收益。

## 已实施的预处理修复（v3）

进一步推进中，已修复上述全部删除空白的缺陷，改为折叠空白并保留词间空格；新增规则剔除包含空中文/英文括号、空引号、空书名号的整段。缺失内容不能靠删除空符号恢复，因此不拼接残句。测试同时保留 `New York`、`2020年（第一阶段）`，避免无差别删除英文、日期或正常括注。

复用已下载分片生成 `data/processed/wiki-zh-5m-v3`，没有网络下载。训练 3,504 篇、5,002,763 字符；验证 110 篇、150,105 字符；词表 4,814 token。自动核查训练集不含本规则针对的空字段标记；不代表其他抽取损坏或语病已全部消除。测试集文件由 ID 划分流程产生，本轮没有用它评分模型。v3 词表、文章集合与旧版不同，loss 不能直接跨语料比较，旧模型不得通过精确 `--resume` 加载到新词表。

配置 `configs/pretrain/wiki_zh_medium_v3.toml` 已准备，20 步 MPS 冒烟训练成功，结果在 `runs/diagnosis/v3-smoke/`；22 项测试通过。尚未在 v3 上正式训练，尚无生成质量收益证据。下一轮应从随机初始化，以相同预算对照，并另外固定共同评估文章和词表策略，不能把文章改变或词表改变带来的 loss 差当成单纯清洗收益。默认百科处理命令现在输出 v3，历史 v2 数据保持冻结。
