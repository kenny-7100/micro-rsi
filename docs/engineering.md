# 工程与实验约定

本文记录实现、数据和验证的具体要求；项目目标与长期协作规则见 [AGENTS.md](../AGENTS.md)。涉及对应工作时遵循本文。

## 面向学习者的实现方式

- 自行编写或维护的文档优先使用中文，包括 README、设计说明、学习笔记和经验记录；注释和协作说明也优先使用中文，代码标识符采用清晰的英文。第三方下载或引入的文档可以保留原文，无需强制翻译。
- 面向中文母语学习者解释概念；命令、路径、API 名称和技术专有名称保留原文，必要时首次出现时补充中文含义。代码示例保留可直接执行的语法，不为翻译改写标识符。
- 关键机制尽量直接用 PyTorch 实现，使 token、embedding、因果注意力、loss、反向传播和采样过程可以阅读与解释。
- 每次引入新机制时解释其目的、输入输出和关键张量形状；注释解释原因，避免逐行复述代码。
- 优先进行小规模、可快速反馈的实验。不得将样例生成效果表述为已具备可靠的理解、事实或对话能力。

## 工程与依赖

- 使用 Python 3.12、uv 和 src 包布局。安装使用 `uv sync`，执行使用 `uv run`；依赖写入 `pyproject.toml` 并提交 `uv.lock`。
- 核心代码放在 `src/micro_rsi/`，脚本仅做薄封装，避免业务逻辑散落在脚本或 notebook 中。
- `data/` 管数据读取和批处理，`tokenization/` 管 token 编解码及词表持久化，`models/` 管网络和前向传播，`training/` 管优化与检查点，`inference/` 管生成，`evaluation/` 管指标与验收。
- 实验配置放在 `configs/`，采用 TOML。当前 `tiny_char.toml` 已接入训练入口并校验字段；新增配置能力须同步实现读取和校验。
- 优先使用 PyTorch MPS；支持 CPU 回退，接口允许显式指定设备。不得默认依赖 CUDA。
- 增加第三方库前，先判断标准库或现有依赖是否足够；避免仅为未来设想增加重量级依赖。

## 数据、实验和检查点

- 原始数据放在 `data/raw/`，处理结果放在 `data/processed/`，检查点放在 `artifacts/checkpoints/`，日志和实验记录放在 `runs/`。这些内容默认不提交 Git。
- 使用语料时记录来源、使用许可、预处理方法和数据划分。先按文档或连续区段切分训练与验证集，再构造窗口，避免重叠窗口泄漏。
- 实现训练时显式设置随机种子，记录完整配置、设备、tokenizer 信息和训练/验证指标；说明跨设备数值复现的限制。
- 检查点应携带模型参数、模型配置、tokenizer 元数据和训练步数；支持恢复训练时还需保存优化器等必要状态。推理不得依赖仍在内存中的训练对象。
- 保持模型与 tokenizer 可独立保存和加载；后续更换 tokenizer 或增加训练阶段时，不应重写整个训练/推理流程。
- 不自动下载大型语料、预训练权重或启动长时间训练；除非用户任务已明确授权。常规依赖安装、短小验证和当前任务需要的本地修改可直接执行。

## 验证与完成标准

- 常规静态检查：`uv run ruff check .` 与 `uv run ruff format --check .`。
- 有测试后执行 `uv run pytest`。测试聚焦实际行为与风险，例如 token 编解码一致性、因果遮罩、标签对齐、保存加载及生成长度；不要只验证实现细节。
- 纯目录和文档调整无需新增测试；涉及训练或推理时，先跑短小 smoke test，再按需要进行训练验收。
- 第一阶段验收应包括：独立验证集 loss 相对初始化明显下降；固定前缀的训练前后生成对比；退出训练进程后单独加载并推理。
- 汇报时区分已实现、已验证和计划中的能力，给出可执行命令与真实限制。未跑过的训练、测试或性能数据不得当作事实。


## 恢复训练与学习率

`train --resume path/to/last.pt` 恢复模型、AdamW、窗口采样随机数和设备随机数状态；`max_steps` 为累计目标，不是追加步数。恢复前校验数据 SHA256、词表、模型配置、批大小、种子和设备类型；运行及检查点目录必须为空，原实验保留。

`min_learning_rate` 默认等于 `learning_rate`，保持旧配置恒定学习率；设置较低值后，从累计 `schedule_start` 到 `max_steps` 余弦衰减。改变终点会改变曲线，分段运行要想精确复现，必须保持实际每步学习率相同。恢复后的 `initial.pt` 表示续训起点，不是随机初始化。CPU 测试验证恒定学习率、含 dropout 的分段恢复与连续训练逐位相同；MPS 短跑已确认起点指标一致，跨版本或设备不保证逐位复现。
