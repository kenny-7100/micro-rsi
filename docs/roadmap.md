# 学习路线与验收

## 当前：工程准备

建立包、目录、依赖和环境验证命令。尚未实现 tokenizer、模型、训练器或文本生成；配置文件仅作为下一步实现的起点。

已确认第一版从随机初始化开始，以《呐喊》训练中文字符级模型，跑通后加入《彷徨》。详细选择依据、起始参数、实施节点与待核实事项见 [第一阶段训练方案](stage-one-plan.md)。当前仅完成探索与方案沉淀，尚未下载语料或开始实现训练流程。

## 第一阶段：自回归续写

1. 核实《呐喊》的具体来源、版本与使用许可，按篇目或连续区段划分训练集和验证集。
2. 实现字符级 tokenizer，理解文本、token ID 和词表的对应关系。
3. 构建输入与右移一位的标签；可先用 bigram 跑通 loss 和生成基线。
4. 实现小型 Decoder-only Transformer，逐步理解 embedding、位置表示、因果注意力、前馈网络和残差连接。
5. 实现优化循环与验证记录，先短跑测量速度、内存和 loss，再确定训练预算。
6. 保存模型、配置与 tokenizer，独立进程加载后逐 token 生成。

验收：验证集 loss 相对初始化下降；固定前缀的训练前后输出有可见改善；独立加载可推理。能够解释标签对齐、因果遮罩、交叉熵和采样的作用。

## 后续：逐步提高实用性

- 将字符级 tokenizer 替换为子词 tokenizer，对比相同预算下的效果。
- 扩展语料与模型，观察上下文长度、参数量和训练 token 数的影响。
- 在保存加载与评估接口稳定后增加指令数据、对话格式和监督微调。
- 按真实任务建立评估集，再决定是否需要检索、工具调用或推理服务。

这些是演进方向，不代表当前已经支持；每阶段只引入有学习或效果收益的复杂度。
