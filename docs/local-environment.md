# 本地环境经验

## uv 缓存与项目位于不同文件系统

2026-11-10 初始化时，项目位于 `/Volumes/kenny/github/micro-rsi`。`uv sync` 提示无法建立硬链接，随后自动回退为文件复制，安装成功。

uv 缓存与虚拟环境位于不同文件系统时可能出现此提示。项目已在 `pyproject.toml` 中设置：

```toml
[tool.uv]
link-mode = "copy"
```

后续同步直接采用复制，避免重复尝试硬链接。这是安装文件的方式设置，不是模型运行性能优化；迁移环境后可根据磁盘布局重新判断。

## 验证 MPS 的基础计算能力

当前设备为 Apple M2、16 GB 统一内存。初始化时使用 Python 3.12.11、PyTorch 2.15.0，以下命令均通过：

```sh
uv run micro-rsi doctor
uv run micro-rsi doctor --device cpu
```

`doctor` 除查询设备可用性外，还执行张量平方求和、反向传播，并核对梯度。第一次命令实际选择 MPS，第二次选择 CPU。

这能验证基础设备计算与自动求导，无法证明未来模型的全部算子兼容性、训练速度或内存需求。增加模型后仍需进行实际训练短跑；升级 PyTorch 或迁移设备后可重新执行这些命令。

## 检查点元数据应使用普通类型

首次 100 步短跑能完成前向、反向和保存，但随后 `torch.load(..., weights_only=True)` 失败：检查点元数据直接保存了 `torch.__version__`，该值在当前 PyTorch 中是 `TorchVersion` 对象，安全加载器没有默认允许它。

修复方式是存储 `str(torch.__version__)`，让版本信息成为普通字符串；继续保留 `weights_only=True`。检查点除张量外的元数据优先使用普通字典、列表、数值和字符串，不通过关闭安全加载绕过格式问题。

已增加完整训练入口测试：训练两个小步、加载 initial/best/last 三份检查点并生成，避免仅测试简化检查点而漏掉真实元数据问题。失败短跑保留在 `runs/nahan-smoke/` 及对应检查点目录，修复后的有效短跑使用 `nahan-smoke-v2`，二者不混合作为验收结果。

## 验证区段短于上下文长度

按每篇末尾 10% 划分后，部分短篇验证区段不足 257 字符。仅采样完整窗口会静默忽略这些篇目。当前将短区段补齐到窗口长度，补齐标签设为 -100，由交叉熵忽略；完整验收另逐区段遍历全部目标，含短尾。

固定窗口抽样 loss 和完整遍历 loss 的权重、上下文重置方式不同，不应混为同一个指标。每种指标分别比较初始化与最佳模型。

## Wikimedia API 的 429 限流

一次顺序获取《彷徨》11 个正文页面时，第 11 个页面返回 HTTP 429。程序已将每个成功响应分别缓存，重新运行只请求缺失页后完成；此次无需重复下载已缓存内容。遇到 429 时停止请求，稍候再运行，不做快速循环重试；大批量采集应节流并遵守站点政策。


## Unicode规范化会影响中文标点与词表

本轮百科初次清洗采用NFKC，发现它会把中文逗号等全角标点转换为ASCII；旧中文前缀因此含词表外字符。正式数据改用NFC，保留中文标点，另建`wiki-zh-5m-v2`数据目录，正式训练前预检全部可读性前缀。避免静默删除未知字符或把不同清洗版本的指标混在一起。

## 批量开放数据替代逐页抓取

数百万字符实验采用Hugging Face固定版本的Wikimedia Parquet单分片下载，一次请求获得约121MiB文件；不逐页访问受限站点。下载后验证SHA-256，保留数据卡、来源ID和URL。新增PyArrow用于流式按批读取Parquet，无需安装整套datasets框架或加载整个中文百科。
