# 第一阶段首轮训练与验收记录

日期：2026-11-10。结论：从随机初始化到本机训练、检查点与独立中文 token 续写的完整流程已跑通；数值验收通过，生成仍不连贯，不具备实用写作或对话能力。

## 环境、数据与执行

- Apple M2、16 GB 统一内存；macOS 26.5.1；Python 3.12.11；PyTorch 2.15.0；训练设备 MPS，float32。
- 语料为《呐喊》14 篇小说，61,832 个训练字符、6,877 个验证字符；词表 2,413，参数 1,443,840。来源和清洗细节见 [语料说明](corpus-nahan.md)。
- 配置：4 层、128 维、4 个注意力头、前馈 512 维、上下文 256、dropout 0.1；批大小 16、AdamW、学习率 0.0003、权重衰减 0.01、梯度裁剪 1.0、种子 42。
- 每 100 步使用同样的 10 批固定窗口检查训练与验证 loss；最佳检查点按此验证估计选择，未额外用完整遍历结果挑选模型。

实际执行命令：

```sh
uv run micro-rsi prepare --download
uv run micro-rsi train --max-steps 100 \
  --run-dir runs/nahan-smoke-v2 --checkpoint-dir artifacts/checkpoints/nahan-smoke-v2
uv run micro-rsi train
uv run micro-rsi verify
uv run micro-rsi generate --checkpoint artifacts/checkpoints/nahan/best.pt \
  --prompt '夜里，我一个人走在路上，' --max-new-tokens 80 --device cpu
```

第一次短跑暴露了检查点版本元数据的安全加载问题，修正后使用新的短跑目录，详见 [环境经验](local-environment.md)。不要将失败短跑当作最终基线。

训练命令拒绝覆盖非空目录；如需复现实验，用新的运行与检查点目录。语料已存在时复用原件，重新清洗应指定新输出目录。跨设备或版本不保证逐位复现。

## 耗时与内存

有效 100 步短跑平均每步约 0.060 秒。正式 2,000 步的训练更新耗时 119.99 秒，总耗时 134.85 秒（含评估、检查点及固定样本生成），平均更新耗时 0.060 秒/步，共处理 8,192,000 个预测位置，包含重复采样。

训练结束时 MPS 当前张量分配约 64.9 MiB，驱动分配约 1.06 GiB。这些是末尾采样值，包含缓存等开销，**不是峰值内存或进程总内存**。

## 独立进程验收

训练进程退出后执行 `verify`，从 initial/best 两份检查点分别加载，不依赖训练内存对象。先核对数据 SHA-256，再计算固定窗口和完整区段指标，最后生成相同的三组样本。

| 指标 | 随机初始化 | 最佳检查点（700 步） |
| --- | --- | --- |
| 固定验证窗口 loss | 7.795805 | 4.635202 |
| 完整验证区段 loss | 7.801076 | 4.672867 |
| 完整验证区段中已知目标的 loss | 7.799763 | 4.605908 |

完整区段评分覆盖 6,863 个目标，即每篇验证区段除首字符外的全部字符，其中 6,795 个已知目标、68 个未知字符目标。按不重叠的最长上下文块评分，各块重置上下文；与固定随机窗口的上下文及权重不同，两类 loss 分别比较，不混为同一个指标。两者都明显低于初始化。

三组前缀均成功生成 200 个新 token，未输出未知 token；MPS 独立加载的文本与训练进程保存样本完全一致。另以 CPU 独立生成 80 个新 token，命令成功退出。

## 固定前缀生成对比

以下为同一新前缀、temperature 0.8、种子 42 下的原始输出，不挑选或润色。展示前 100 个新字符，完整的三组各 200 token 样本保存在本地实验目录。

前缀：`夜里，我一个人走在路上，`

初始化续写：

```text
句俐格世痕尺捉丧何黎叨相讳站徊爱酒钩连沂根顽田告忐既庇师呵奶则救嚏嗡姐呜式雅人雀倒限拳蚣驶兼诺研搀按讨答…摸褒许臂业匀功职丧谭睫袄康列废坐月荚环氏殖胸洗丫辈吩右像尺示权，谦逊藕簪聚眶》愉脏拷惧心披聚井
```

最佳检查点续写：

```text
他一家不出了。
何庄看前走近呢。
小去，根一个人便要气，一个人都是两个人都哄人的，一拳头，你知道可惜不答………………”“不肯亲到头说，“你这时候，女儿洗然不出来，大家里，那大家的…”他们我自己心”
“
```

可以看到随机字符串变成了带有“一个人”“你知道”等词组、标点和局部句式的片段，但“他一家不出了”等内容仍不通顺，远不能保持故事或语义连贯。第一阶段的生成改善仅限这些局部规律，不能表述为模型已掌握中文。

对三组最佳续写（不含前缀）分别与每个训练区段进行最长连续精确匹配，长度为：

| 前缀类别 | 最长训练文本连续匹配 |
| --- | --- |
| 训练文本前缀 | 5 字符 |
| 验证文本前缀 | 6 字符 |
| 新组合前缀 | 5 字符 |

这三份样本没有出现长段逐字复述，但该检查无法证明模型不记忆原文，也没有覆盖所有前缀、种子和采样参数。重复标点、词组拼接和不合理搭配均明显存在。

## 后续学习建议

先阅读 [实现导读](stage-one-guide.md)，用现有检查点尝试不同前缀与 temperature，理解模型的行为。下一轮按计划加入《彷徨》，处理新增词表并做对照；不优先单纯延长本轮训练，因为验证曲线已显示这样会加重过拟合。

当前没有 bigram 实现、恢复训练 CLI、自动早停、KV cache、子词 tokenizer 或指令微调。本轮模型的局部续写已经满足机制实验的最低验收，若以流畅中文为标准则尚未达到，需要更多数据及后续实验。
