# 第一阶段：中文自回归模型训练方案

记录日期：2026-11-10。本文保留已确认的选择和起始方案；当前实现见 [实现导读](stage-one-guide.md)，实际验证结果见 [实验记录](stage-one-results.md)。下文起始预算不代表性能或质量承诺。

## 已确认的目标与选择

- 在 Apple M2、16 GB 统一内存的 Mac 上训练并推理，优先使用 PyTorch MPS，保留 CPU 支持。
- 从随机初始化开始，自己实现小型 Decoder-only Transformer，不使用已有预训练模型的权重。PyTorch 提供计算与自动求导，不提供已经学会中文的参数。
- 第一版使用中文字符级 tokenizer，学习根据前缀逐 token 续写，不要求对话、指令遵循、事实可靠性或通用写作能力。
- 语料先选鲁迅《呐喊》，完整流程跑通后再加入《彷徨》。此选择已由用户确认；现已使用 Gutenberg 27166 版本，具体来源与处理见 [语料说明](corpus-nahan.md)。
- 以理解数据、模型、loss、反向传播和生成机制为首要目标；后续按需求扩展实用性。

## 为什么选《呐喊》

现代白话小说包含叙述、对话、标点和段落，适合观察中文续写；单部作品范围明确，便于检查数据和训练效果。候选来源为 [中文维基文库](https://zh.wikisource.org/) 和 [Project Gutenberg](https://www.gutenberg.org/)，实施时已选定并获取 Gutenberg 27166，原始文件与许可说明保留在本地；详见语料说明。

局限是语料规模小、年代与作者风格鲜明，模型可能记忆原文、重复或生成不连贯的句子。单部作品足以做机制实验，不必先凑到几 MB；也不能据此承诺生成质量。

## 语言能力与扩展边界

模型架构本身不限中文，但可表示的文本由 tokenizer 决定，生成能力由训练数据和训练效果决定。中文字符词表不会天然覆盖全语种；预先加入英文字母也不会自动获得英文能力。

以后可以混合中英文训练，或训练新的双语版本。更换、扩展词表时需要保持 ID 映射一致，并处理 embedding 与输出层尺寸变化。UTF-8 字节级表示能覆盖多种文本，但不等于模型学会所有语言，暂不作为第一版方案。

## 实施步骤

### 1. 取得与整理语料

- 核实来源、文本完整性、版本与许可，记录地址和获取日期，保留原始文件；清洗通过脚本完成，保证可重复。
- 统一 UTF-8，优先选统一的简体版本；若需要繁简转换，记录工具和转换方式，不混用未经说明的版本。
- 去除导航、页码和非正文说明，保留正文标点、段落换行与篇目边界。
- 按篇目中的连续区段预留约 10% 验证数据，先切分再构造窗口；窗口不跨篇目或训练/验证边界。根据篇目长度调整划分并记录规则。
- 统计正文字符数、各划分大小与词表覆盖情况。验证集用于开发选择；未来需要独立报告泛化能力时，另留测试集。

### 2. 字符级 tokenizer 与样本

- 用训练文本构建字符到整数 ID 的映射，预留未知字符 token；保存词表及编码规则。
- 验证数据的未知字符统计覆盖率；输入前缀出现未知字符时明确提示，不静默删除。大量未知字符意味着 loss 比较需要重新审视。
- 输入和标签错开一个 token：输入 `我 家 的 后 面`，目标为 `家 的 后 面 有`。字符只是示例，不代表语料引文。
- 起始上下文长度为 256；一个完整样本需要 257 个连续 token，分别产生 256 个输入与标签。
- 可先实现 bigram 基线验证数据、loss 和采样链路，再替换为 Transformer；它是辅助学习步骤，不替代最终模型。

### 3. 模型起始结构

| 参数 | 起始选择 |
| --- | --- |
| 模型类型 | Decoder-only Transformer，因果自注意力 |
| 层数 | 4 |
| embedding 维度 | 128 |
| 注意力头数 | 4 |
| 前馈网络维度 | 512 |
| 上下文长度 | 256 token |
| 位置表示 | 可学习的位置 embedding |
| dropout | 0.1 |
| 参数规模 | 约百万级，依实际词表和实现计算 |

计算链路：token ID → 字符与位置 embedding → Transformer 层 → 词表分数。输入形状为 `[批大小, 上下文长度]`，输出为 `[批大小, 上下文长度, 词表大小]`。

因果遮罩保证每个位置不能看到未来答案。权重从随机初始化开始，偏置或归一化参数按其规则初始化为零或一，不要求所有参数都随机。

### 4. 训练设置与短跑

| 项目 | 起始选择 |
| --- | --- |
| 数值精度 | float32 |
| 优化器 | AdamW，具体权重衰减值在实现时明确记录 |
| 学习率 | 0.0003，先用简单设置 |
| 批大小 | 16 |
| 梯度裁剪 | 最大范数 1.0 |
| 随机种子 | 42，并记录设备与配置 |
| 首次短跑 | 约 100～200 步，按实际检查需要调整 |
| 首轮观察预算 | 约 2,000 步，依短跑和验证表现调整 |
| 验证间隔 | 起始每 100 步，另保留初始化验证基线 |

每步取窗口、前向预测、计算交叉熵、反向传播并更新参数。交叉熵衡量模型给真实后续 token 分配的概率，正确 token 概率越低，惩罚越大。

先检查有限 loss、梯度更新、保存加载和生成能否运行；用小段数据拟合确认训练链路能学习。小段拟合成功不等于验证集泛化成功。

短跑测量步耗时和可获取的内存指标，检查 MPS 算子兼容性，再决定正式预算。当前不承诺分钟数、训练时长或生成质量。

批大小 16、长度 256 时，每步约 4,096 个预测位置，2,000 步约 819 万个训练 token 位置，包含对原始文本的重复采样，不是 819 万个不同语料 token。语料少时应观察过拟合，不能只延长训练。

### 5. 验证、检查点与独立推理

- 固定验证样本或完整遍历验证集，使用评估模式、不计算梯度，让初始化与训练后的 loss 可比较。
- 记录训练和验证 loss；训练 loss 下降而验证 loss 持续上升时检查过拟合；验证 loss 用于选择最佳检查点，同时记录实际步数。
- 保存模型参数、模型配置、tokenizer、训练步数；恢复训练另需优化器和必要随机状态等信息。记录可复现限制。
- 退出训练进程后独立加载检查点，输入前缀，循环预测、采样并追加 token。超过上下文长度时采用明确的截断策略。
- 起始生成设置为 200 个新 token、temperature 0.8；对比实验保持前缀、采样设置和随机种子一致。特殊 token 的生成处理在实现时明确。
- temperature 调节随机程度，不能弥补训练不足，也不保证更低温度一定更好。

## 验收与学习成果

| 验收项 | 应保留的证据 |
| --- | --- |
| 学到了预测规律 | 同一验证集上，训练后 loss 相比随机初始化明显下降，记录具体数值 |
| 生成行为改善 | 固定前缀、采样设置下的训练前后输出，避免只挑好看的结果 |
| 推理流程完整 | 独立进程加载模型、配置与 tokenizer 并完成续写的命令与结果 |
| 结果局限清楚 | 记录重复、未知字符、文本不连贯及复现训练原文的情况 |

前缀覆盖训练文本、验证片段和由已知字符组成的新前缀。出现训练原文需要检查记忆现象，不能把复述直接当作泛化能力。

学习者应能解释：输入与标签为何错开；因果遮罩如何防止偷看；loss 衡量什么；参数如何更新；为什么训练可并行计算多个位置、生成通常逐 token 进行；temperature 怎样影响采样。

## 实施节点与当前状态

1. 数据就绪：来源核实、清洗、切分、tokenizer 和数据窗口。
2. 链路就绪：模型、训练、验证、检查点和生成实现完成，短跑检查通过。
3. 首轮验收：完成预算内训练，交付 loss 记录、生成对比和独立推理方式。

当前已实现语料、tokenizer、窗口、Transformer、训练与独立推理入口，配置文件已接入训练器。基础计算、关键行为测试和 MPS 短跑已经验证；正式训练与验收的具体状态、数值以 [实验记录](stage-one-results.md) 为准。

本轮实施由用户明确要求以目标模式推进，包含语料准备和首轮训练。后续新增实验仍遵循具体任务授权与预算，不将本次授权延伸为无限训练。

## 加入《彷徨》时的对比实验

首轮完成后，可以加载自己训练出的检查点继续训练，或用两部作品从零训练作为对照。新增字符需显式处理词表和模型参数兼容性；继续训练时混合保留《呐喊》的训练数据，降低遗忘风险。保持验证划分可追溯，记录数据、词表和训练预算变化，避免把多个变量的变化误归因为单一原因。
